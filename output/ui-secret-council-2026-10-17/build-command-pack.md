# COUP — The Secret Council
## คู่มือคำสั่งสร้าง UI และภาพประกอบ

ฉบับ 1 • 18 ตุลาคม 2026

คู่มือนี้แปลงภาพคอนเซปต์ทั้ง 13 หน้าเป็นชุดคำสั่งที่นำไปใช้สร้าง UI จริง ภาพการ์ด และภาพพื้นหลังได้ โดยล็อกภาษาภาพให้เป็นชุดเดียวกัน และลดรายละเอียดตกแต่งให้เหลือเท่าที่ช่วยสร้างบรรยากาศกับบอกสถานะเกม

ภาพต้นแบบใช้เป็นแนวทางเรื่องพาเลตต์ ภาพพิมพ์แกะไม้ และองค์ประกอบโต๊ะประชุมเท่านั้น รายละเอียดการเล่นต้องยึดจากโค้ดใน workspace เสมอ

## 1. ทิศทางภาพ

**ชื่อทิศทาง:** The Secret Council — เกมไพ่ในห้องประชุมลับ

ผู้เล่นต้องอ่านสถานะโต๊ะ ไพ่ เหรียญ และตาของตัวเองได้เร็ว บรรยากาศทางการเมืองอยู่ในภาพตัวละครและลายเส้นประกอบ ไม่ใส่ลายทุกพื้นที่ องค์ประกอบหลักจึงเป็นกระดานที่เรียบชัด มีพื้นกระดาษอุ่น กรอบหมึกน้ำเงินเข้ม และจุดเน้นสีแดงชาด

ภาพประกอบใช้ลายเส้นพิมพ์แกะไม้ร่วมสมัยแบบ editorial illustration: เงารูปทรงชัด พื้นผิวเป็นลายเส้นน้อยและควบคุม ไม่ใช้ภาพคนสมจริง ไม่วาดเครื่องประดับยิบย่อยจนดูเป็นฉากแฟนตาซีหรือภาพ AI ที่ใส่รายละเอียดเกินเหตุ

**ภาพจำของ UI:** วงโต๊ะสภากลม มีที่นั่งผู้เล่นวางรอบวง ไพ่ส่วนตัวอยู่ในพื้นที่ของเจ้าของหน้า เหตุการณ์หรือแอคชั่นอยู่กลางพื้นที่ตัดสินใจ ภาพนี้ต้องคงอยู่แม้ซ่อนภาพพื้นหลัง

### ตัวอักษร

- **Wordmark COUP:** ตัวพิมพ์ใหญ่ serif ที่คอนทราสต์สูง เช่น Cormorant Garamond หรือ Georgia; ใช้เป็นหัวแบรนด์เท่านั้น อย่าทำให้ใหญ่จนเบียดเนื้อหา
- **หัวเรื่องภาษาไทย:** Noto Serif Thai หรือ serif ภาษาไทยที่อ่านชัด ใช้น้ำหนักกลางถึงหนา
- **ข้อความและปุ่ม:** Noto Sans Thai หรือ sans-serif ภาษาไทยที่อ่านง่าย
- **รหัสห้อง เวลา และตัวเลขเกม:** IBM Plex Mono หรือ monospace สำรอง เพื่อให้เลขเรียงตรงกัน
- ใช้ fallback ที่ติดตั้งได้เมื่อโหลดฟอนต์ภายนอกไม่ได้ ตรวจสระและวรรณยุกต์ไทยจริงก่อนส่งงาน

### รูปทรงและความหนาแน่น

- กรอบหลักใช้มุมโค้งปานกลาง 8–14 px หรือมุมกระดาษตัดเล็กน้อย เลือกแบบเดียวทั่วระบบ
- เส้นแบ่งบาง 1 px เงาสั้นและนุ่ม ใช้ขอบซ้อนเฉพาะการ์ดที่ถูกเลือก
- พื้นผิวกระดาษเป็น noise อ่อนมาก หากมองเห็น grain ก่อนเห็นข้อความ ให้ลดความเข้ม
- พื้นหลังทั้งหน้าใช้ภาพหรือ texture ไม่เกินประมาณ 10–15% ของความเด่นของ UI
- จำกัดลวดลายสลัก/แถบธงให้เป็นจุดเน้นรอบขอบภาพหรือบริเวณ header ไม่ใส่หลังตัวหนังสือ
- จัดลำดับสายตา: สถานะปัจจุบัน → ผู้เล่น/ทรัพยากร → การตัดสินใจ → ประวัติและกติกา
- ข้อความทุกชิ้นต้องเป็น DOM/text ของหน้าเว็บ ไม่ฝังลงในภาพที่เจน

## 2. Prompt กลางล็อกสไตล์

คัดลอกข้อความนี้ไปวางก่อน prompt ของหน้าหรือภาพที่ต้องการสร้าง:

**STYLE LOCK**

ออกแบบสำหรับเกมไพ่หลอกลวง COUP ในธีม The Secret Council. ใช้พาเลตต์ paper #F2EBDD, paper-light #FFF9EE, deep ink #102735, ink-soft #274253, vermilion #B6322C และ accent teal #3E918A กับ muted lilac #A687B0. ตัวอักษรหัวเรื่องใช้ serif ที่มีบุคลิกแบบสิ่งพิมพ์เก่า; ข้อความ UI ใช้ sans-serif ภาษาไทยที่ชัด; ตัวเลขและรหัสใช้ monospace. ภาพตัวละครเป็นภาพพิมพ์แกะไม้ร่วมสมัยแบบ editorial: รูปทรงเรียบ อ่านออกเมื่อย่อ สีแบนจำกัด ลายเส้นแรเงาบาง ไม่สมจริง ไม่แฟนตาซี พื้นหลังเป็นกระดาษพิมพ์หรือภาพสถาปัตยกรรมสภาแบบจาง. ใช้กรอบกระดาษและแถบหมึกน้ำเงินเข้มเป็นตัวประกอบ. เว้นพื้นที่หายใจ ใช้ลายตกแต่งเฉพาะขอบหรือจุดสำคัญ. ให้ UI และการอ่านกติกามาก่อนภาพ. รักษาระยะ ขนาด องศาแสง น้ำหนักเส้น และการวางตัวละครให้สอดคล้องกันทุกหน้า/ทุกภาพ. ห้ามใส่ตัวหนังสือ โลโก้ ตัวเลข UI หรือสัญลักษณ์กติกาลงในไฟล์ภาพ เว้นแต่ prompt ระบุชัดว่าเป็นภาพ UI เต็มหน้าและให้คัดข้อความตามต้นฉบับ

## 3. Prompt สำหรับสร้างหน้าเว็บ

ใช้ prompt นี้กับ coding agent เพื่อให้ทำ UI ใน repo จริง อย่าใช้ image generator สร้าง screenshot แล้วนำมาแสดงแทนหน้าเว็บ

### คำสั่งหลักสำหรับ coding agent

คุณกำลังปรับ UI เกม COUP ใน repo ปัจจุบันให้อยู่ในทิศทาง The Secret Council. ก่อนแก้โค้ด ให้อ่าน AGENTS.md (ถ้ามี), src/App.tsx, src/components/Lobby.tsx, Login.tsx, GameBoard.tsx, PlayerActionPanel.tsx, OpponentList.tsx, ActionLog.tsx, RulesModal.tsx, Tutorial.tsx, VictoryScreen.tsx, src/core/gameEngine.ts, src/core/roomCommands.ts, src/core/gameCommands.ts, types และ tests ที่เกี่ยวข้อง แล้วสรุปหน้าจอ สถานะข้อมูล และกติกาที่โค้ดรองรับในปัจจุบัน

ทำ UI ด้วย React และ CSS/Tailwind ที่มีอยู่ใน repo. รักษา Firebase/session, callable commands, server-authoritative game engine, data privacy และพฤติกรรมเดิม เว้นแต่ส่วนที่ระบุชัดว่าเป็นการเพิ่ม readiness ในล็อบบี้. ใช้ STYLE LOCK ในคู่มือนี้เป็นแหล่งกำหนดภาพ. อย่าเปลี่ยนระบบหลังบ้านเพื่อให้ตรงกับข้อความที่ภาพ AI วาดผิด

ทำ layout ให้เหมือนเกมกระดานดิจิทัลจริง ไม่ใช่ภาพ poster: ทุกข้อความและปุ่มเป็น HTML จริง, มี keyboard focus, semantic labels, responsive desktop/tablet/mobile, scroll ที่ใช้งานได้, contrast ชัด และ reduced-motion. ตัดภาพฉากหลังให้จางและเว้นพื้นที่ให้แผงเกม. สร้างแผง ไพ่ เหรียญ ปุ่ม และกรอบด้วย HTML/CSS/SVG ก่อนพิจารณาภาพ bitmap. ใช้ bitmap เฉพาะภาพตัวละครและภาพสลักประกอบที่กำหนดในหัวข้อ asset prompts. อย่าใช้ภาพเจนแทนข้อความควบคุมหรือข้อมูลแบบ live.

ยึด game engine เป็นแหล่งจริงเรื่องผู้เล่น ไพ่ลับ ไพ่เปิดเผย แอคชั่น เหรียญ ตา การตอบโต้ และผู้ชนะ. ก่อนเพิ่มปุ่มหรือสถานะ ให้ตรวจ command และ validation ที่มีอยู่. ห้ามเปิดเผยไพ่ลับของคู่แข่ง หรือใช้ภาพ avatar/ท่าทางที่ทำให้เดาบทบาทในมือได้. หากต้องเพิ่ม readiness ตามหัวข้อล็อบบี้ ให้ทำเป็นสถานะ public ที่ server ตรวจสิทธิ์และความถูกต้องได้; อย่าปลอมสถานะด้วย React local state อย่างเดียว.

ส่งมอบเมื่อ layout ทุกสถานะมีข้อความจริงและการใช้งานจริง สถานะ loading/empty/error/disabled อธิบายได้ แอนิเมชันไม่ขัดการตัดสินใจ และการเปลี่ยนแปลงผ่าน checks ที่ repo กำหนด. สรุปไฟล์ที่เปลี่ยนกับข้อสมมติที่เพิ่ม.

### Prompt สร้างหน้าเว็บทีละหน้า

ต่อ STYLE LOCK ด้วย prompt ของหน้าที่ต้องการ อย่าให้โมเดลเดา copy หรือกติกาเพิ่มเติม

**01 — เข้าเล่น / Login**

สร้างหน้าเข้าเล่น COUP ที่มีงานเดียวคือให้ผู้เล่นตั้งชื่อและเริ่ม session. ใช้หน้า 16:9 desktop และจัดเรียงใหม่เป็นคอลัมน์บนจอแคบ. ใช้ wordmark COUP กับ subtitle THE SECRET COUNCIL ขนาดพอดี. มีหัวข้อภาษาไทย กรอกชื่อผู้เล่น ปุ่มเริ่มเล่น และปุ่มวิธีเล่นและกติกา. ภาพสถาปัตยกรรมจางอยู่ด้านข้างหรือขอบล่างเท่านั้น ให้ฟอร์มเป็นจุดเด่น. แสดงสถานะ session loading/เริ่มไม่ได้ด้วยข้อความที่ระบบส่งจริง. ห้ามสร้าง email/password/login provider ที่ระบบไม่มี.

**02 — Lobby ก่อนสร้าง/เข้าห้อง**

สร้างหน้าล็อบบี้ที่แยกสองทางเลือกชัด: สร้างห้องใหม่ กับเข้าห้องด้วยรหัส. ใช้ช่องรับรหัสแปดตัวอักษรตาม validation ปัจจุบัน โดยแสดงเป็นช่องเดียวหรือช่องแยกแปดช่องแต่ต้องวางและ paste รหัสได้. ใช้ตัวอย่างที่ถูกต้องตาม alphabet ปัจจุบัน A–H, J–N, P–Z; ห้ามใช้ I/O. มีทางไปกติกาและออกจากระบบ. ไม่ต้องมีภาพตัวละครใหญ่ ใช้ลายสภาบางที่ขอบ.

**03 — Lobby ในห้อง / โต๊ะหกที่นั่ง**

หน้านี้เป็นจุดเด่นของดีไซน์. แสดงโต๊ะกลมมองจากด้านบนหรือเฉียงเล็กน้อย สร้างโต๊ะและเก้าอี้ด้วย CSS/SVG ให้สัดส่วนคงที่; ไม่เจนโต๊ะเป็นภาพแบน เพราะผู้เล่นและสถานะต้อง live. วางเก้าอี้หกตัวรอบวงเสมอ เรียงเท่ากันและมีช่องว่างระหว่างกัน. ที่นั่งที่มีผู้เล่นแสดง avatar แบบกราฟิกเรียบ ชื่อผู้เล่น เหรียญ? ไม่ต้องแสดงเหรียญก่อนเกม และป้ายข้อความพร้อม/ยังไม่พร้อม. ที่นั่งว่างแสดง silhouette/วงเส้นกับคำว่า “ที่นั่งว่าง” แบบเบา. ระบุที่นั่งเจ้าของห้องและที่นั่ง “คุณ” โดยกรอบหรือป้ายเล็ก ไม่ขยายตัวละคร.

ด้านบนโต๊ะแสดง “ห้อง [รหัส 8 ตัว]” ปุ่มคัดลอกรหัส และสถานะจำนวนผู้เล่น n/6. แถบการทำงานด้านล่างมีปุ่ม “พร้อมเล่น” หรือ “ยกเลิกความพร้อม” สำหรับผู้เล่นทุกคน, ปุ่ม “เริ่มเกม” สำหรับเจ้าของห้องเท่านั้น, และปุ่มออกจากห้อง. ตามข้อเสนอในคู่มือนี้ ปุ่มเริ่มเปิดเมื่อมีผู้เล่นอย่างน้อย 2 คนและผู้เล่นทุกคนที่นั่งอยู่พร้อมแล้ว; ไม่จำเป็นต้องเติมครบ 6 คน. ถ้ายังไม่ครบให้บอกชัดว่าใครยังไม่พร้อม. ผู้เล่นอื่นกดพร้อมได้ แต่เห็นสถานะของทุกที่นั่ง. ถ้าสถานะเริ่มเกมถูกปฏิเสธเพราะ roster เปลี่ยน ให้รีเฟรชสถานะและแจ้งว่าห้องเปลี่ยนแล้ว.

**การเคลื่อนไหวที่ล็อกไว้สำหรับล็อบบี้**

- เมื่อสร้างห้องเสร็จ ให้เกิดวงโต๊ะและเก้าอี้หกที่นั่งด้วย transition สั้นครั้งเดียว; avatar เจ้าของห้อง fade/slide เข้าที่นั่ง ไม่หมุนหรือเด้ง
- เมื่อผู้เล่นเข้ามา ให้แสดง avatar ในเก้าอี้ว่างด้วย opacity 0→1 และ translateY ระยะน้อย ใช้เวลาประมาณ 160–220 ms เล่นครั้งเดียว
- สถานะยังไม่พร้อมเป็นท่านั่งผ่อนคลาย/สี ink-soft พร้อมข้อความ “ยังไม่พร้อม”
- เมื่อกดพร้อม ให้ท่านั่งเปลี่ยนเป็นเอนตัวเข้าหาโต๊ะเพียงเล็กน้อย ป้าย Teal “พร้อม” ปรากฏพร้อม check แบบ fade/scale สั้น ๆ ใช้เวลาประมาณ 180–240 ms เล่นครั้งเดียว
- ยกเลิกพร้อมให้กลับท่ากลางอย่างนุ่มนวล ไม่ทำ shake
- เมื่อทุกคนนั่งพร้อม ให้ขอบโต๊ะหรือแผ่นกลางโต๊ะเกิด highlight Teal หนึ่งครั้ง แล้วหยุด. ห้าม pulse ต่อเนื่องหรือกะพริบ
- ท่าทางเป็น silhouette/illustration เรียบ ไม่สร้าง animation rig ที่สมจริงจนดูแปลก. สถานะต้องอ่านจากข้อความกับ icon ได้ แม้ปิด motion.
- รองรับ prefers-reduced-motion ด้วยการตัดการเคลื่อนและใช้สี/opacity เปลี่ยนทันที
- อย่าทำให้การเคลื่อนไหวแย่งความสนใจจากปุ่มพร้อมหรือปุ่มเริ่ม

**หมายเหตุการเชื่อม readiness กับระบบ:** ปัจจุบัน UI/room command ยังไม่มีคำสั่งเปลี่ยนสถานะพร้อม แม้ type อาจมี field รองรับ. การทำงานจริงจึงต้องเพิ่มข้อมูล isReady ที่ sync จาก server, คำสั่งเฉพาะให้ผู้เล่นเปลี่ยนสถานะของตัวเอง, validation ว่าห้องยังเป็น lobby และผู้เล่นยังอยู่, ตั้งค่าเริ่มต้น false เมื่อเข้าห้อง, reset readiness เมื่อเริ่ม/กลับเข้าล็อบบี้ และตรวจ “ทุกคนพร้อม + อย่างน้อย 2 คน + เจ้าของห้อง” ในคำสั่ง start ฝั่ง server. ป้องกันผู้เล่นแก้สถานะคนอื่นได้. นี่เป็นข้อกำหนดของแนวคิด readiness ใหม่ ไม่ใช่พฤติกรรมปัจจุบัน.

**04 — กระดาน ถึงตาคุณ**

แสดงผู้เล่นที่ยังอยู่และจำนวน influence สาธารณะโดยไม่เปิดไพ่คว่ำ. ไพ่ที่เปิดเผยแล้วแสดงบทบาทได้. แสดงไพ่ส่วนตัวจาก private data ในพื้นที่ “ไพ่ของคุณ”. ให้กึ่งกลางระบุ “ถึงตาคุณแล้ว” และส่วน action panel แสดง 7 แอคชั่นพอดี: Income, Foreign Aid, Coup, Tax, Assassinate, Steal, Exchange. Contessa ใช้บล็อก Assassinate ไม่ใช่แอคชั่นที่ 8. แสดงค่าใช้จ่าย เงื่อนไข และ disabled reason ให้ตรง game engine. ใส่ประวัติแบบย่อด้านข้างหรือเป็น drawer. เวลาเล่นเป็นเวลาสะสมจาก gameStartedAt ไม่ใช่เวลาตอบสนองนับถอยหลัง.

**05 — เลือกเป้าหมาย**

ใช้เมื่อเลือก Coup, Assassinate หรือ Steal. แสดงเฉพาะผู้เล่นอื่นที่ยังมีชีวิตเป็นตัวเลือก. เลือกแล้วกรอบ Vermilion และข้อความยืนยันอ่านชัด. แสดงต้นทุนถูกต้อง: Coup 7, Assassinate 3; Steal ไม่มีต้นทุน. เตือนผลต่อเป้าหมายสั้น ๆ. ยกเลิกได้ก่อนส่งคำสั่ง. ห้ามแสดงว่าผลสำเร็จก่อน server ตอบ.

**06 — ตอบโต้แอคชั่น**

แผงเหตุการณ์อ่านได้ในทันที: ผู้ใช้แอคชั่น ชื่อแอคชั่น บทบาทที่อ้าง เป้าหมาย และผลของการปล่อยผ่าน. ให้ปุ่มที่กติกาอนุญาตเท่านั้น. ปุ่มจับโกหกมีเฉพาะ action ที่อ้างบทบาทได้ ได้แก่ Tax, Assassinate, Steal, Exchange; ไม่ใส่ให้ Income, Foreign Aid, Coup. Foreign Aid ถูกบล็อกด้วย Duke แต่จับโกหกตัวแอคชั่น Foreign Aid ไม่ได้. การจับโกหกผิดเสีย influence ตาม engine. แสดงเวลานับถอยหลัง 15 วินาทีเฉพาะตอนผู้เล่นนี้ต้องตอบ; เมื่อหมดเวลา engine/client ปล่อยผ่านตามกติกาปัจจุบัน. แสดงว่าปิด modal ไม่เท่ากับตอบผ่าน.

**07 — มีผู้เล่นบล็อกแล้ว**

แสดงผู้เล่นที่เริ่ม action, ผู้เล่นที่ประกาศ block, บทบาท block ที่อ้าง, และ action ต้นฉบับ. ปุ่มคือ “ยอมรับการบล็อก” (ปล่อยผ่าน) และ “จับโกหก”. ไม่มี block ซ้อน. ถ้าทุกคนยอมรับ action ถูกยกเลิก. ถ้าท้าการ block แล้วผู้บล็อกมีบทบาทจริง ผู้ท้าต้องเสีย influence; ถ้าไม่มี ผู้บล็อกเสีย influence. ไม่แสดงไพ่ลับก่อนผลถูก server เปิดเผย.

**08 — เลือกไพ่เปิดเผย**

แสดงเฉพาะไพ่ส่วนตัวที่ยังใช้ได้ของตัวเอง. ผู้เล่นเลือกหนึ่งใบเพื่อเสีย influence. แยกไพ่เปิดเผยแล้วอย่างชัดเจนและห้ามให้เลือกซ้ำ. แสดงว่าเมื่อ influence เหลือศูนย์จะตกรอบ. หน้านี้ไม่มีปุ่มยกเลิกที่ทำให้หลีกเลี่ยงผลบังคับได้.

**09 — Exchange**

แสดงตัวเลือกจากไพ่ที่ยังใช้ได้ของตัวเองและไพ่จั่วใหม่ใน private state. ให้เลือกเก็บจำนวนเท่าไพ่เดิมที่ยังมีชีวิต; แสดงตัวนับ n/n. การ์ดที่เลือกมี check กับกรอบ แต่ไม่พลิกหรือสั่น. ไพ่อื่นคืนกองหลังยืนยัน. ไพ่ที่เปิดเผยแล้วไม่เข้าการเลือกสลับ.

**10 — กติกา**

ทำเป็นหน้าหรือ modal ที่อ่านยาวได้ มี navigation ไปภาพรวม บทบาท แอคชั่น และการตอบโต้. แสดงบทบาทห้าแบบและการใช้จริง. เน้นข้อบังคับ Coup เมื่อมี 10 เหรียญขึ้นไป; Coup ราคา 7. มีปุ่มเริ่ม tutorial และกลับเกม. ข้อความต้องมาจากกติกาปัจจุบัน ไม่คัดตามข้อความที่โมเดลเจนในภาพตัวอย่าง.

**11 — บทเรียน**

ใช้โครงสร้างบทเรียนหกขั้นที่มีอยู่: เริ่มจากไพ่ในมือ, เลือกแอคชั่น, ลองบล็อก, ก่อนจับโกหก, เปิดเผย/สลับไพ่, พร้อมเข้าเล่น. แยกไพ่สถานการณ์จำลองออกจากข้อมูลจริง. ตัวเลือกที่ตอบแล้วแสดงคำอธิบาย แต่ไม่ส่ง command เข้าเกมจริง. มี progress, ย้อนกลับ, ถัดไป, ออกจากบทเรียน.

**12 — ผู้ชนะ / เกมจบ**

แสดง winner ที่มาจาก server, ปุ่มกลับดูกระดาน/ปิดผล และการเริ่มเกมใหม่ตามสิทธิ์ admin ที่มีจริง. ผู้เล่นที่ไม่ใช่ admin เห็นข้อความรอเจ้าของห้อง. ไม่เพิ่มคะแนน อันดับ รางวัล หรือสถิติที่เกมไม่ได้เก็บ.

**13 — Mobile**

ทำ mobile layout เป็น UI จริง ไม่ย่อ screenshot desktop. ในสถานะตอบโต้ให้ event และปุ่มหลักอยู่ก่อน ส่วนรายชื่อคู่แข่ง ประวัติ และไพ่ตัวเองเป็นส่วนพับหรือ navigation ด้านล่าง. ปุ่มสูงแตะสะดวก. โต๊ะหกที่นั่งอาจกลายเป็นวงย่อด้านบนกับรายการผู้เล่นหกแถว โดยยังเก็บ seat order และข้อความ ready. ตรวจว่าหน้าจอเล็กไม่ซ่อนปุ่มพร้อม/ยกเลิกพร้อมหรือปุ่มออก.

## 4. Prompt สำหรับเจนภาพการ์ดบทบาท

สร้าง “ภาพ portrait art สำหรับการ์ด” แยกจากกรอบและตัวหนังสือ. ทำห้าภาพด้วย prompt ฐานเดียวกัน แล้วเติม role-specific line ทีละใบ. ให้ภาพเป็น family เดียวกัน ไม่เปลี่ยนมุมกล้องหรือสไตล์ระหว่างตัวละคร.

### Prompt ฐานสำหรับ portrait ทุกใบ

ภาพประกอบ portrait ครึ่งตัวของบทบาท COUP ในสไตล์ contemporary woodcut editorial illustration. ตัวละครยืนหรือนั่งตรง มองเยื้องจากกล้องเล็กน้อย สีหน้าแน่วแน่แต่ไม่แสดงท่าทางเกินจริง. จัดตัวละครกึ่งกลาง เผื่อขอบรอบศีรษะและไหล่สำหรับ crop เป็นกรอบการ์ดแนวตั้ง. ใช้แสงด้านซ้ายบนแบบเดียวกัน พื้นหลังเป็นผิวกระดาษกับลายสถาปัตยกรรมบางจาง. เส้นแกะสลักใหญ่ไม่ถี่ เงาเป็นแถบรูปทรง สีแบน 3–4 สี มี ink navy และ ivory เป็นแกน พร้อม accent สีประจำบทบาท. ไม่มีกรอบการ์ด ตัวอักษร โลโก้ ตัวเลข ไอคอน เหรียญ อาวุธที่ดูสมจริง หรือฉากเต็ม. พื้นหลังโปร่งใสถ้าทำได้; ถ้าไม่ได้ให้พื้นหลังสีเดียวเรียบสำหรับตัดออก. ภาพต้องอ่านออกเมื่อย่อขนาดไพ่.

**เติมบรรทัดบทบาทท้าย prompt ฐาน:**

- **Duke:** รัฐบุรุษวัยกลางคนขึ้นไป เสื้อคลุมทรงเรียบ ดูมั่นคงและสุขุม; accent muted teal/ink.
- **Assassin:** บุคคลลึกลับในเสื้อคลุมสี vermilion/ink; สีหน้าเงียบและมีสติ; ห้ามยกมีดหรือทำท่าคุกคาม.
- **Captain:** กัปตัน/ผู้ควบคุมกองเรือในชุดเรียบ มีรายละเอียดปกเสื้อเพียงเล็กน้อย; accent teal/blue; ไม่ต้องมีเรือชัดในมือ.
- **Ambassador:** นักการทูตผู้สุขุมในเครื่องแต่งกายทางการที่เรียบ; accent muted lilac.
- **Contessa:** ขุนนางหญิงหรือผู้คุ้มกันในชุดทางการสีเข้ม; accent dusty lilac/rose; ดูมั่นใจไม่ยั่วยุ.

ใช้ภาพ 10-rules.png หรือ 04-game.png เป็น reference ด้านลายเส้น/สีเท่านั้น ไม่คัด layout, ตัวหนังสือ หรือภาพหลายตัวละครในภาพอ้างอิงมาใส่. ถ้าระบบสร้างภาพรองรับ seed/reference weight ให้ล็อก reference เดียวกันกับทั้งห้าใบ.

### กรอบการ์ดที่ให้หน้าเว็บวาด

อย่าเจนกรอบการ์ดรวมกับภาพตัวละคร. วาดกรอบด้วย CSS/SVG: อัตราส่วนแนวตั้งคงที่, พื้น paper, เส้น ink บาง, role accent เป็นแถบเล็ก/ขอบบน, portrait crop ตรงกัน, แล้ว render ชื่อบทบาทด้วย HTML. หน้าการ์ดลับใช้หลังไพ่ลายเส้น emblem เดียวใน navy, ไม่ต้องมีตัวหนังสือ. ไพ่ที่เปิดเผยให้เพิ่มป้าย “เปิดเผยแล้ว” และลด saturation อย่างชัดเจน. ไพ่ลับคู่แข่งห้ามโหลด portrait role ที่แท้จริง.

### Prompt ไพ่หลัง

ลายด้านหลังไพ่ COUP แบบสมมาตร เรียบสำหรับใช้ซ้ำทุกใบ: พื้น deep ink #102735, ลายเส้นสลักวงกลม/ตราสภาเล็กตรงกลาง ใช้เส้นสี paper จางกับ vermilion เพียงจุดเดียว, ขอบเส้นคู่บาง. ไม่มีตัวอักษร ไม่มีเลข ไม่มีบทบาทเฉพาะ ไม่ใช้ลายละเอียดหนาแน่น; อ่านเป็นลวดลายเดิมแม้ย่อเล็ก. สร้างเป็นภาพ flat 2D ตรงหน้า หรือเป็น SVG ในโค้ดหากต้องการความคมชัดทุกขนาด.

## 5. Prompt สำหรับภาพพื้นหลังประกอบ

ใช้พื้นหลังเท่าที่จำเป็น. ถ้า CSS ทำได้คมและเบากว่า ให้ใช้ CSS. พื้นหลังต้องไม่มีข้อความและต้องไม่บอกสถานะผู้เล่น.

### A. Login / หน้าเข้าเล่น

ภาพประกอบสถาปัตยกรรมห้องสภาแบบภาพพิมพ์แกะไม้ร่วมสมัย องค์ประกอบหลักอยู่ริมซ้ายและริมล่าง มีพื้นที่สงบโล่งกว้างด้านขวาสำหรับ panel เข้าเล่น. ใช้สี ink, ivory และ vermilion แบบจาง ไม่ใส่บุคคลที่ระบุตัวตนได้ ไม่ใส่โต๊ะเก้าอี้เด่นจนชนกับฟอร์ม. รายละเอียดระดับกลางค่อนต่ำ คอนทราสต์ลดลงหลังบริเวณที่วางข้อความ. Flat editorial print, no text, no logo, no UI, no card, no watermark.

### B. Lobby / โต๊ะหกที่นั่ง

แนะนำให้ทำโต๊ะกลมและเก้าอี้หกตัวด้วย SVG/CSS เพื่อให้จำนวน เก้าอี้ และตำแหน่งผู้เล่นสัมพันธ์กับข้อมูลจริง. ถ้าต้องการภาพประกอบ ให้เจนเพียงลายเส้นสถาปัตยกรรมสภาจาง ๆ เฉพาะขอบภาพบนพื้น paper. เว้นกลางภาพว่างสำหรับโต๊ะ UI. ห้ามเจนคน ห้ามเจนเก้าอี้ที่นั่ง occupied ห้ามเจนป้ายพร้อม และห้ามฝังรายละเอียดที่อาจซ้ำกับ DOM.

### C. Game board / ห้องประชุมระหว่างเกม

ภาพสลักวงโต๊ะประชุมสภาจากมุมสูงเกือบตรง เน้นวงกลมใหญ่ที่แยกจากผู้เล่นได้ พื้นที่กลางวงเรียบโล่งสำหรับ event panel. ใช้ ink navy และ paper เป็นหลัก มี vermilion เพียงธง/จุดเล็ก. ลด contrast และลายเส้นบริเวณที่วางแผงการ์ด. ไม่มีคน ไม่มีไพ่ ไม่มีตัวหนังสือ ไม่มี UI ไม่มีเหรียญ. ภาพเป็นฉากประกอบ ไม่ใช่ภาพถ่าย/3D และไม่เกิน 10–15% visual weight.

**ข้อแนะนำการใช้ไฟล์:** ใช้ภาพพื้นหลัง A เป็นภาพหน้า Login เท่านั้น. ล็อบบี้ใช้ paper CSS กับเส้นขอบอาคารเบา ๆ เพื่อให้โต๊ะเป็นจุดเด่น. กระดานใช้ภาพ C แบบ opacity ต่ำหรือใช้เพียงฉาก CSS หากภาพรบกวนไพ่. Rules, modal และ exchange ใช้พื้น paper เดียวกัน ไม่ต้องสร้างภาพใหม่รายหน้า.

## 6. Prompt สำหรับไอคอนและสถานะ

สำหรับเหรียญ ปุ่ม check, shield, timer, seat, card back, action glyphs ให้สร้าง inline SVG หรือ CSS icon set ที่ stroke และมุมเดียวกัน. ถ้าจำเป็นต้อง gen sprite sheet ให้สั่งเป็น flat icon sheet พื้นโปร่งใส ทุกไอคอนขนาดเท่ากัน วางตาม grid ระยะคงที่ ใช้ stroke หนาเดียว, สี ink + vermilion + teal ไม่เกินสามสี, ไม่มีแสงเงา/3D, ไม่มีตัวอักษร. แต่สำหรับ UI จริง SVG แยกชิ้นให้เข้าถึงด้วย screen reader ง่ายกว่า.

สถานะ Ready ใช้ check ในวงกลม teal และคำว่า “พร้อม”; Not ready ใช้ clock/dot สี ink-soft และคำว่า “ยังไม่พร้อม”. ห้ามใช้ท่าทางภาพเพียงอย่างเดียวเป็นตัวบอกสถานะ.

## 7. Negative prompt กลาง

ใช้ท้ายคำสั่งภาพทุกภาพ:

Avoid photorealism, 3D game render, glossy casino aesthetic, black-and-gold luxury cliché, neon, fantasy filigree, ornate borders everywhere, tiny dense engraving, excessive texture, fake old parchment stains, dramatic smoke, glowing eyes, random runes, duplicated people, malformed hands, inconsistent faces, different camera angles across role portraits, busy text backgrounds, fake Thai lettering, gibberish, pseudo-UI, watermarks, logos, unintended labels, generated buttons, invented game rules, exposed hidden cards, and decorative detail that competes with the interface. Keep the result quiet, readable, restrained, and consistent with the shared reference.

## 8. ตรวจรับงาน

### ภาพและสไตล์

- เปิดภาพทุกหน้าเทียบกันที่ 100% และ thumbnail: ภาษาภาพต้องมาจาก family เดียวกัน
- เห็นพื้น paper, ink frame, vermilion action และภาพแกะไม้ในสัดส่วนใกล้เคียงกัน
- ภาพประกอบไม่แย่งสถานะเกม; ถ้าจำข้อความได้ก่อนอ่านปุ่ม ให้ลดรายละเอียด/contrast
- ห้ามใช้ AI-generated text ใน assets. ข้อความใน UI ต้องอ่านได้จริงจาก browser
- ไพ่ทั้งห้ามุม มุมมอง แสง ความสูงตัวละคร และความหนาเส้นตรงกัน

### UI และกติกา

- ขนาดห้อง 2–6 คน; รหัส 8 ตัวอักษรและไม่ใช้ I/O ตาม validation ปัจจุบัน
- ที่นั่ง lobby มี 6 ตำแหน่งคงที่; occupied count ตาม roster จริง; ไม่มีคนหรือไพ่ใน seat placeholder ที่ทำให้เข้าใจผิด
- ไพ่ของคู่แข่งเปิดเผยเฉพาะที่เสียไปแล้ว; ไพ่ที่ยังใช้ได้ซ่อนชื่อบทบาท
- มีแอคชั่น 7 อย่าง; Contessa เป็น defensive role ไม่ใช่ action tile
- มีตั้งแต่ 10 เหรียญต้องเลือก Coup; Coup 7, Assassinate 3; Foreign Aid +2, Tax +3, Income +1, Steal ได้สูงสุด 2
- ผู้ตอบเห็น response countdown 15 วินาทีเฉพาะเมื่อตัวเองต้องตอบ; game clock แสดงเวลาเล่นสะสมคนละส่วน
- Exchange เลือกเก็บเท่าจำนวน influence ที่ยังมี; ไพ่ที่เปิดเผยแล้วไม่ถูกสลับ
- Lobby ready เป็นงานเพิ่ม: toggle sync จาก server; start มีอย่างน้อย 2 คนและทุกคนที่นั่งพร้อมตามข้อเสนอในคู่มือนี้. ตรวจ permission/server validation อย่าพึ่ง client display
- ทดสอบ keyboard, focus, contrast, มือถือ 320–390 px, prefers-reduced-motion, loading/empty/error และสถานะ disabled

## 9. การจัดเก็บ assets ที่แนะนำ

เก็บเฉพาะภาพที่ใช้จริงใน public/assets/secret-council/ หรือโฟลเดอร์ assets ตาม conventions ปัจจุบัน. ใช้ชื่อไฟล์คงที่ เช่น role-duke.webp, role-assassin.webp, role-captain.webp, role-ambassador.webp, role-contessa.webp, card-back.svg, bg-login.webp, bg-board.webp. ไม่จำเป็นต้องมี bg-lobby หากโต๊ะกับพื้น CSS ชัดอยู่แล้ว.

เก็บไฟล์ต้นฉบับที่สร้างไว้แยกจากไฟล์ production. บันทึก prompt ของ asset ไว้คู่กับไฟล์เพื่อสร้างซ้ำได้. ก่อนเพิ่มไฟล์ใหญ่ ให้ลอง crop/resolution ที่ใช้จริงและบีบอัดเป็น WebP/AVIF; รักษารายละเอียดเส้นแกะสลักพออ่านได้. เพิ่มเฉพาะ asset ที่จำเป็นจริง ไม่สร้างหลาย background เพียงเพื่อให้ทุกหน้าแตกต่างกัน.
